El informe usa como referencia de formato `U4_Informe.docx`: encabezado institucional, tabla con nombres/matrículas, curso, profesor, actividad y fecha, desarrollo, evidencias, conclusiones y bibliografía. No reemplaza los informes históricos de U2/U3 y no modifica el caso TechStore de U4.

Las métricas se identifican por ejecución/commit. Las capturas son ejecuciones reales del Swagger del núcleo en una base ficticia de CI. Los ejemplos estáticos de documentación no se presentan como pruebas ejecutadas. Los diagramas son vistas del código y del análisis, no capturas de una aplicación que no exista.

El reporte distingue lo implementado, lo simulado y lo diseñado. Los pendientes funcionales de R16 permanecen. El [registro de cierre](../docs/pia/CIERRE.md) identifica el estado final de integración y despliegue después de preparar estos documentos.

Antes de subir a NetAcad, revisar en Word/PowerPoint el contenido y las conclusiones como equipo. La presentación incluye una guía del recorrido para apoyar la defensa; no sustituye demostrar el sistema en vivo.
